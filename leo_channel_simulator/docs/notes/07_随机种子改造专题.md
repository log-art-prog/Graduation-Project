## 1. 为什么原来不可复现

原代码直接用 `np.random.randn() / uniform() / exponential()`，
这些走的是 NumPy **全局随机状态**，程序每次启动由系统时间重新初始化，
所以阴影、衰落、统计指标每次都变。

## 2. 两种方案对比

| 方案 | 写法 | 评价 |
|------|------|------|
| 全局种子 | `np.random.seed(42)` | 简单但全局共享，函数顺序一变全乱 |
| 局部生成器（采用） | `rng = np.random.default_rng(42)` 当参数传 | 随机源可控、互不污染 |

API 替换对照：
```
np.random.randn()        → rng.standard_normal()
np.random.uniform(a,b)   → rng.uniform(a,b)
np.random.exponential(s) → rng.exponential(s)
```

## 3. 三层改造结构

### 第一层：fading.py（每个衰落函数）
```python
def generate_xxx(..., rng: np.random.Generator = None):
    """docstring 必须在函数体第一条"""
    if rng is None:
        rng = np.random.default_rng()   # 兜底，允许单独调用
    ...rng.standard_normal()...
```
- 4 个函数全部加 rng；
- 内部调用子函数必须 `rng=rng` 透传（瑞利/莱斯/多径三处）；
- 没有随机调用的 `calculate_fading_metrics` 不用加。

### 第二层：channel_model.py（分发中心）
```python
simulate_channel(..., seed=None, rng=None):
    if rng is None:
        rng = np.random.default_rng(seed)
    # 把 rng 下发给阴影和小尺度衰落
```

### 第三层：多环境用 spawn 分流
```python
parent = np.random.default_rng(seed)
children = parent.spawn(len(environments))   # 分裂独立子流
```
要点：子流按**位置编号**分配。某环境排在第几位，就用第几条流。

### 入口：main.py
```python
SEED = 42
simulate_multiple_environments(..., seed=SEED)
```
想每次随机：设 `SEED = None`。

## 4. 易踩的坑（本次都遇到过）

1. 参数名笔误：写成 `rnd` 但函数体用 `rng` → NameError。
2. 只改函数体、不加 rng 参数 → NameError。
3. 内部调用忘记透传 rng → 子函数仍走全局源，复现性被破坏（最难发现）。
4. docstring 写在 `if rng is None:` 之后 → `__doc__` 变 None。
5. 用 spawn 后误以为"换个列表位置结果要相同"——实际按位置编号，位置不同用不同子流是正确的。

## 5. 验证方法（必须实测）

- 同种子两次运行，终端输出 `Compare-Object` 零差异；
- `np.array_equal` 比较 shadow_db、small_scale_amp；
- 不同种子结果必须不同（防止"假固定"）；
- 多径抽头和延迟都要比对（确认透传全覆盖）。
